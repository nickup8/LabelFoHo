# Перенос в существующий проект

## 1. Подключение оформления

Перенесите `css`, `js` и `assets` в каталог статических файлов проекта. Сохраните взаимное расположение папок либо исправьте пути в HTML, `@font-face` и ссылках PDF.

На корневом элементе установите `data-theme="mono"`. Подключите три CSS-файла в порядке из README. Не удаляйте `white.css`: это завершающий слой утверждённой палитры. Идентификатор `mono` — внутреннее имя именно белого варианта.

Используйте разметку общей оболочки из `index.html`: шапку, hero, workspace, steps, stage, footer, input файла и области уведомлений. Сохраните ID элементов, пока работаете с контроллером `ui.js`.

CSS использует общие селекторы `body`, `main`, `nav`, `button`, `table`. Подключайте его на экранах FoHo, а не глобально для посторонних разделов вашего проекта.

## 2. HTML / JS или компоненты существующего фронтенда

Файлы написаны на обычных HTML, CSS и JavaScript. Их можно использовать напрямую либо перенести в компоненты уже выбранного в проекте фреймворка. Этот архив не навязывает новый стек, сборщик, роутер, API или схему данных.

Функции в `js/ui.js` соответствуют экранам:

| Функция | Содержимое |
| --- | --- |
| `renderHeader`, `renderSteps`, `renderFooter` | Общая оболочка |
| `renderUpload` | Загрузка файла |
| `renderAudit`, `showRow` | Таблица и подробности строки |
| `renderTemplate` | Форматы этикеток |
| `renderExport` | Подтверждение / создание |
| `renderReady` | Скачивание |
| `renderImporter` | Реквизиты |
| `navigate` | Смена экрана через стандартную анимацию |

В React/Vue и подобных системах используйте функции как источник разметки, перенеся события и состояние в компоненты. Не запускайте `ui.js` поверх дерева DOM, которым уже управляет фреймворк. `motion.js` и направляющую стрелку подключайте после появления соответствующих узлов, с очисткой наблюдателей и анимационных циклов при размонтировании.

## 3. Места подключения существующей логики

| Место | Сейчас в пакете | При интеграции |
| --- | --- | --- |
| `js/fixtures.js`, `seedReference()` | Две фиксированные строки для просмотра | Подставить данные, уже полученные приложением |
| `addFile()` | Запоминает имя/размер и показывает фиксированные строки | Подключить действующее чтение Excel; не переносить подстановку `sourceRows` |
| `rowErrors()` | Выводит переданный массив `errors` | Передавать результат существующей проверки, не придумывать новые правила |
| `generate()` | Визуальный сценарий на таймерах | Завершать по фактической готовности PDF; убрать таймер готовности |
| `renderReady()` | Фиксированный `assets/reference/foho-labels.pdf` | Подставить URL / Blob реального результата, имя и показатели документа |
| `renderImporter()` | Изменяет реквизиты только в памяти страницы | Подключить существующий механизм сохранения |
| `js/config.js` → `templateUrl` | `null`, ссылка не скачивает файл | Указать URL утверждённого Excel-шаблона |

Не переносите в рабочую обработку данных подстановку `sourceRows`, `seedReference()` и таймер готовности: они нужны только для просмотра вёрстки. Внешние запросы, сохранение в браузере, парсер Excel и PDF-библиотека в пакет не добавлялись.

## 4. Последовательность создания PDF

1. Начало: `state.generating = true`, затем `render()`. Текст обычного экрана и шапка скрываются; остаются крупная объёмная анимация и подпись этапа.
2. Подписи меняются через `setGenerationCaption(0 / 1 / 2)`. При подключении к реальной генерации связывайте их с известными этапами обработки.
3. Готовность: `state.generating = false`, затем `await navigate('ready', { push: false })`. Эта функция вызывает стандартный переход со словами «Скачать PDF».
4. URL файла и сведения о документе должны быть подготовлены до показа `ready`.

Если создание завершилось ошибкой, экран скачивания не открывайте. Используйте обработку ошибок, которая уже есть в вашем приложении; пакет не задаёт новую бизнес-логику.

## 5. Анимации отдельно от контроллера

`window.FohoMotion.sync()` подключает Canvas после его появления в DOM. При смене Canvas повторно вызовите `sync()`.

```js
await window.FohoMotion.transition(
  3,
  () => {
    // Здесь заменить содержимое экрана на готовый результат.
    // После изменения разметки вызвать FohoMotion.sync().
  },
  { label: 'Скачать PDF' }
);
```

Номера сцен: 0 — загрузка, 1 — аудит, 2 — шаблон, 3 — экспорт/скачивание, 4 — импортёр. Второй аргумент вызывается под закрывающим слоем перехода.

## 6. Ресурсы

Единственное растровое изображение интерфейса — оригинальный логотип. Иконки — встроенные SVG; карточки форматов нарисованы CSS; объёмные листы — Canvas. Их не нужно экспортировать в картинки: перенесите соответствующую разметку, CSS и JavaScript.

Шрифт находится локально; копируйте и файл шрифта, и `OFL.txt`. Для белого фона логотип затемняется CSS-фильтром `invert(1)`, исходный PNG не изменён.

## 7. Проверка после переноса

Проверьте все отдельные HTML-точки входа, цепочку шагов, выбор обеих категорий, контур загрузки, направляющую стрелку, ховеры и «Назад», фильтры таблицы, карточку товара, форму импортёра, создание и скачивание. Проверьте размеры окна ноутбука, большой монитор и мобильный экран, а также системный режим уменьшения движения.

Обычные экраны подстраиваются по высоте окна, аудит сохраняет прокрутку. `viewport.js` применяет CSS `zoom` к рабочей области только когда она не помещается. Если в проекте уже есть собственная адаптация оболочки, перенесите это поведение осознанно, не добавляя второе масштабирование поверх первого.
